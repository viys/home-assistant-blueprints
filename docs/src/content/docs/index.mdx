## Choose the behavior

For a shared average across device models, see
[Shared average temperature](./blueprints/sonoff-thermostatic/remote_temperature_average_link_sonoff_thermostatic/).

| You want to… | Look for… |
| --- | --- |
| Use a sensor placed away from the thermostat or radiator | **Remote temperature**: one measured reading is forwarded. |
| Combine several sensors into one reading | **Average temperature**: Home Assistant averages valid readings. |
| Keep several temperature sources separate | **Remote temperature sources**: individual readings go to supported device slots. |
| Make valves follow the panel setting | **Target temperature**: the desired temperature is forwarded, rather than a measured reading. |
| Pause climate control when a door or window opens | **Door and window sensors**: selected contacts supply one combined open or closed input. |

Source counts and behavior depend on the device, firmware, and integration.
Each guide explains its ZHA and Zigbee2MQTT support before you import.

Before importing, check the chosen guide's minimum Home Assistant Core version
and [device support](./getting-started/#check-device-support). Requirements
vary by blueprint.

## Your first automation

1. [Check the prerequisites](./getting-started/#before-importing).
2. Open your device guide and choose a blueprint.
3. Import it, then **create and save an automation** with your devices and sources.
4. Cause a real source update and check the result.

Already using one? Read [Update a blueprint](./updating/).
For setup and connection checks, see [Check your automation](./checking/).
